## Automated visual result (shared)

- Capture harness: Roborazzi 1.76.0 + Robolectric 4.17, SDK 36, mdpi, 430x932, light theme, locale `en`, `ltr`.
- Policy approved by the owner: `channelTolerance` 16, `maxChangedRatio` 0.03, four 20x20 corner ignores.
- Official core compare after correction round 3 (budget 4 per node, 3 used on failing nodes):
  - Passed: splash 0.71%, signin 2.84%, signup 2.31%, cart 1.46%, account 2.55%, wishlist 2.69%.
  - FAILED: details 3.24%, categories 3.34%, productlist 4.60%, home 4.15%.
- Remaining differences are attributed to the following. This is an agent reading, not proven:
  - the status bar band, about 650px (0.16%);
  - Robolectric text anti-aliasing and tracking;
  - image resampling;
  - the dropped SVG filters.
- An automated pass is NOT human approval. Human visual review: `not_run` for all 10 screens.

## Shared decisions

### Tokens and theme
- Token approval is light-only. Dynamic Color is off. `MainActivity` calls `AppTheme(dark = false)`; the generated `AppTheme` has no dark scheme and no dynamic color.
- The theme is generated by figma-compose (config `design/figma/compose/config.json`, files in `ui/theme/generated/`). Do not hand-edit generated files.
- Typography `typography.source06` (SF Pro Text, the iOS status bar font) was removed from the approved tokens (owner-approved). `AppTokens` therefore has no `typographySource06`.
- Fonts: Poppins 300/400/500/600, OFL, from Google Fonts. License marked approved by the owner. Binary match with the Figma render is unverified.
- Generated Material mapping (`ui/theme/generated/AppTheme.kt`):
  - colors: `primary` = `colorSource00`, `onPrimary`/`background`/`surface` = `colorSource02`, `onBackground`/`onSurface` = `colorSource12`, `onSurfaceVariant` = `colorSource21`, `outline` = `colorSource14`, `surfaceVariant` = `colorSource22`;
  - typography: `bodyMedium` = `typographySource07`, `bodySmall` = `typographySource11`, `titleMedium` = `typographySource00`;
  - shapes: `extraSmall` = `radiusSource07` (5dp), `small` = `radiusSource05` (10dp), `medium` = `radiusSource02` (15dp), `large` = `radiusSource00` (20dp), `extraLarge` = `radiusSource08` (30dp).
- Screens read most values directly from `LocalAppTokens` (`colorSourceNN`, `typographySourceNN`, `radiusSourceNN`), not from the Material roles.
- Note for developers: `ui/theme/Theme.kt` (`EcommerceNativeC19Theme`, template default with `dynamicColor = true`) still exists but nothing references it. Do not use it.

### Status bar
- The iOS status bar of the design is not reproduced. The Android native status bar is used (deviation: the top 44px band of the reference is not reproduced).
- `core/ui/DesignStatusBar.kt` reserves a 44dp top band: `max(real status bar inset, 44dp)`. Check the effect on real devices (not verified on a device).
- 21 iOS status-bar assets were skipped.

### Scope narrowing
- 17 nodes (15 component dependency nodes + 2 pre-existing) were moved to `excludedNodes`. Components were derived from the contexts of the 10 screens; their variants were not extracted separately. Owner-approved scope narrowing.

### Navigation
- The bottom bar has 4 tabs: Home, Categories, Wishlist, Account. Cart is not a tab; it opens from the header cart icon.
- Splash -> Sign in after 400 ms (`AFTER_TIMEOUT` from the prototype).
- The prototype uses SMART_ANIMATE. Compose cannot reproduce it, so screens cross-fade: 400 ms linear for Splash -> Sign in, 300 ms ease-out elsewhere (`navigation/AppNavHost.kt`).
- Prototype reactions that lead to nodes outside the 10 screens (for example 562:469, 564:542) are not implemented.

### Assets
- 6 SVG filters (blur / drop shadow) were dropped by the VectorDrawable import. Re-applied in code: the splash glow (`Modifier.blur` on API 31+, radial gradient fallback below) and the heart shadow (`Paint.setShadowLayer`, API 28+).
- 31 Figma `.png` files were actually JPEG and were saved as `.jpg`.
- One 5.4 MB image inflates the APK.

### Capture-harness helpers in `core/ui`
- The Roborazzi/Robolectric harness ignores `TextStyle.lineHeight`, so `TextLineBox.kt` (`Modifier.textLineBox`) and `LineBoxText.kt` were added. They are described as no-ops on devices; this was not verified on a device.
- `DesignStatusBar.kt`: see Status bar above.
- `CoverImage.kt` and `CenteredBorder.kt`: placement helpers that keep fractional offsets / centered strokes like the design (Compose rounds to whole pixels otherwise).

### Missing backend / product contracts (shared)
- Auth, registration and validation; forgot-password; checkout; add-to-cart from wishlist or lists; search; product and category data layer.
- All content is placeholder data in `*SampleData.kt` files (marked `DESIGN PLACEHOLDER`).
- Cart total is not recomputed. The quantity floor of 1 is an assumption. Account edit is local only.

### Untested in this documentation
- Nothing in these files claims a check passed unless listed in "Automated visual result". No device test, accessibility audit, RTL, dark mode or large-font test is claimed.
